# FC1B BIOS dump patch procedure

This is the step by step procedure to decrypt and clear a Dell BIOS master password on the FC1B, CF1B, and 8FC8 suffix family by patching the firmware dump. It requires an external SPI programmer such as a CH341A (set to 3.3 V), a SOIC8 test clip for the flash chip, and a computer to run the patch tool; that is all the equipment you need to unlock the machine. The same patch logic works for all three suffixes because they use the same firmware password storage.

Step 1 dump: power the machine off, disconnect battery and charger, clip onto the SPI NOR flash chip (usually a Winbond, GigaDevice, or Macronix 25-series chip, often 16 MB or 32 MB), and read the full chip twice; verify both dumps are identical and keep the original dump as a backup. A valid full dump contains the Intel flash descriptor at the start of the image.

Step 2 verify: the patch tool checks that the Intel flash descriptor signature bytes 5A A5 F0 0F 03 appear within the first 4096 bytes of the dump. If that signature is not found, the dump is partial or corrupt; do not patch it, re-dump the chip with better clip contact.

Step 3 locate the password entries: inside the first 0x160000 bytes (about 1.4 MB) of the dump, the BIOS variable store holds the password entries. The system or setup password entry starts with the byte pattern 00FCAA (hex bytes 00 FC AA), and the administrator password entry starts with the byte pattern 00FDAA (hex bytes 00 FD AA), each followed by a length field, zeros, and the password hash data. The scan rules for both patterns are the regular expressions 00FCAA[0-9A-F]{2,4}000000 followed by more hex, and 00FDAA[0-9A-F]{2,4}000000 followed by more hex.

Step 4 patch: zero out each matched entry by overwriting its first six bytes. A 00 FC AA system password entry becomes 00 FC 00 00 00 00, and a 00 FD AA administrator password entry becomes 00 FD 00 00 00 00. Dell NVRAM stores four redundant password verification flags, so a dump may contain more than two matching entries; all of them must be zeroed. Save the patched image; the command line tool writes the result as patched_ plus the original file name. After flashing a patched dump, the board starts in Manufacturing Mode where the old password is ignored.

Step 5 flash and boot: write the patched image back to the chip with the programmer, reassemble the machine, and boot. The machine shows a warning like The Service Tag has not been programmed. Enter the machine's service tag, the machine reboots again, and the BIOS password lock is cleared. After that, set a new BIOS password if one is wanted.

Tools for this procedure: DellBIOSTools on GitHub (chromebreakerdev/DellBIOSTools) ships a GUI tab named Dell BIOS Unlocker 8FC8/CF1B that patches these entries exactly, and this workspace ships the same logic as command line tools: run `python3 tools/dell_unlock_image.py --patch dump.bin` for the record-store aware patcher (with --analyze and --guide modes), or `python3 tools/dell_fc1b_unlock.py dump.bin` for the simple patcher (add `--scan-only` to just report matches). After flashing, in Manufacturing Mode: write the service tag, run the official BIOS update from the F12 boot menu while still in Manufacturing Mode, then press Alt+F to exit.
