UNLOCKED & LEAKED // 30 · the three regimes

THREE REGIMES BY PASSWORD LENGTH

SHORT

≤ 12 chars

Null padding covers enough of the field that the wrap region (pos 21..31) is also null. All 20 key bytes leak directly.

FULL RECOVERY

MEDIUM

13–21 chars

Null padding shrinks. key[11..19] start being used at password positions only, once each, no second occurrence. Blind zone grows in the middle of the password.

PARTIAL :: middle blind

LONG

≥ 22 chars

Wrap region now holds encrypted password. Counter-intuitively gives back the ends: key[0..(PWD_LEN-22)] is now used at two password positions, dual-position trick recovers them.

PARTIAL :: ends back

THE BLIND ZONE: AND HOW IT FALLS

Past 12 chars, key[11..19] are each used at one position only (pwd[12..20]) and echo nowhere: up to 9 bytes that never leak from that one record. A 32-char password recovers as ~23 known + 9 blind.

But the DVAR store is a log, old passwords are never erased, and the key depends only on the device and the first byte. So any earlier password of ≤ 12 chars sharing the same first character leaked the whole key. Lift it from the old record, apply it to the new one: blind zone gone.
